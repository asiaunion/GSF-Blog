## 0.1 HARD vs FLEX — 잠금 범위 (v2.2 · SSOT)

에이전트·문서가 “주 N편·N시간”을 다시 잠그지 않도록, **닫는 것**과 **여는 것**을 여기서만 가른다.

### HARD (엄격 — 위반 시 재논의·롤백 대상)

| # | 규칙 |
|---|---|
| 1 | **refresh 범위 = WRITING_GUIDE §1–4 표면** — title · 도입(~200자, 쿼리의 답) · 질문형 H2(± meta). **본문 전체 재작성·spine/데이터/가설 층 재작성 금지** (본문 1절 2–4문장 보강은 예외·여력 시에만, 기본 트랙 아님) |
| 2 | **AdSense 재신청 직전 ~2주**: title·표면 **대량** 변경 금지 (심사 표면 안정). 그 창에서는 색인·채널·소규모 정합만 |
| 3 | **하루·한 배치에 수십 편 일괄 `modDatetime`/대량 동시 수정 금지** (조작 신호). 스프린트 가속은 가능하되 “전량 같은 날”은 금지 |
| 4 | **YMYL**: 단정·권유·보장 표현 신설 금지 (title·H2·도입 포함) |
| 5 | **slug/URL 변경 금지** · 허브·카테고리 재배정 금지 |
| 6 | **JA 신규 발행 동결** · 게이트 A 전 AdSense 재신청 금지 · 헤드 키워드 전용글·니치 피벗 금지 |
| 7 | **우선순위 원칙**: GSC 실측·백로그 순으로 §1–4를 먼저 — “아무 글이나 전량”이 아님 |

### FLEX (열어 둠 — 잠금·상한·의무 아님)

| 항목 | 취급 |
|---|---|
| 주당 refresh/신규 **편수** | 가이드라인만 (예: 주 2는 *예시*). 여력·복수 에이전트·스프린트 창에 따라 **올리거나 내려도 됨** |
| Joseph/에이전트 **작업 시간·강도** | 표의 분·시간은 참고치. 초안 위임·일괄 루브릭 허용 |
| T1→대기→T3 **층위 대기** | 측정용 옵션. §1–4를 **한 패스에 번들**하는 것이 기본으로 허용 |
| refresh 70% / 신규 30% | **방향** (기존 자산 우선). 주간 슬롯 수를 고정하지 않음 |
| 주간 캘린더·최소 루프 시간표 | **예시 루틴**. 바쁜 주는 생존 버전만 |
| 대조군 D·코호트 편수 상한 | **권고** (측정에 도움). 케이던스 잠금으로 쓰지 않음 |

> **문서 작성 규칙**: 이후 개정에서 “주 N편 상한·금지”를 HARD로 재삽입하지 말 것. 숫자는 FLEX 예시 또는 “권고”로만.

## 0. 무엇이 바뀌는가 — 놓쳤던 것 전수 대조

기존 프로세스(AUTHOR_OPS + Writing SOP)는 **원고 품질**에는 강했지만, 검색에서 이기는 설계가 앞뒤로 비어 있었다. Sprint §10.1 진단 그대로: "주제를 빠르게 정하고 발행"은 있었고 "이길 쿼리를 정하고 설계"가 없었다.

| # | 놓쳤던 것 (기존) | v2에서 (근거) |
|---|---|---|
| 1 | **쿼리가 설계 입력이 아님** — 제목은 원고 완성 후 문학적으로 (은유형 제목·평균순위 62.77의 원인) | 쿼리 확정 → **title/H2 골격을 원고보다 먼저** (N1–N2, Sprint §10.2) |
| 2 | **SERP 경쟁 확인 없음** — 이길 수 없는 쿼리에도 발행 | SERP 정찰 5분 게이트 — 막히면 더 긴 꼬리로 (N1, §3.1) |
| 3 | **3언어 동시 직역 발행** — Low value 인상의 원천 | JA 신규 동결 · KO+EN만 · **언어별 독자용 문서** 체크 (N5–N6, A3 4–7) |
| 4 | **내부링크가 발행 체크에 없음** — 링크 0 글 9편 발생 | 발행 세트 필수 2개 (tokyoLife 1 + urbanInvestment 1) (N7-③) |
| 5 | **발행하고 끝** — 색인 요청·핑·배포 루틴 부재 | 발행 후 **7종 세트** (N7) — GSC 색인·IndexNow·네이버 큐 |
| 6 | **발행 후 추적 없음** — 어떤 글이 어떤 쿼리에서 몇 위인지 모름 | 쿼리 원장 기록 + 14d/28d 재측정 (N7-⑦, R5) |
| 7 | **기존 글 수정 프로세스 자체가 없음** | refresh 트랙 신설 — 한 층 원칙·백로그→백필 큐 (Part R) |
| 8 | **네이버 배포가 발행과 따로 놂** | "그 주 refresh/발행 = 그 주 네이버 게시" 동주 결합 (N7-⑥, R4) |
| 9 | **YMYL 가드가 본문에만** — 제목 층 잔존 (§8.4) | title·H2에도 가드 적용 (N2, A3-2) |
| 10 | **GEO(AI 검색) 관점 부재** | 도입 200자 front-load + FAQ JSON-LD + Bing/IndexNow (N5, N7) |
| 11 | **essay까지 같은 틀 강제 위험** | essay 면제 명시 — 쿼리 층 안 탐, 고유명사 1개+내부링크 2개만 (§4) |

원고 품질 장치(데이터 우선·티키타카·Decision Log·Bear Case·수치↔출처 매핑·terminology lint)는 **전부 유지**된다 — 버리는 것이 아니라 앞뒤를 채우는 것이다.

## 0.5 운영 우선순위 — P0/P1/P2 (v2.1 · 과설계 방지)

이 프로세스의 최대 리스크는 미준수(단계가 많아 3주 차부터 안 지켜지는 것)다. 그래서 전 단계를 **세 티어로 접는다.** 티어는 새 배분이 아니라 **§F.2-1 잠금(콘텐츠 SEO 55 / 채널 30 / 기술 15)의 실행 형태**다.

### 티어 정의

| 티어 | 내용 | 비중(권고) | 절대 기준 (HARD에 가까운 것만) |
|---|---|---|---|
| **P0 — 쿼리→글** (본체) | 이길 쿼리 선정(정찰) → **§1–4 표면**(title·도입·H2) 적용 (WRITING_GUIDE + 루브릭 5문항). 편수 = FLEX | ~55% | **이번 주에 “쿼리를 이기도록 고친 글”이 ≥1편 있는가** (편수 상한 없음) |
| **P1 — 배포** (게이트 유지) | 손댄 글의 네이버 게시 (기존 초안 재구성). 편수 = FLEX (게이트 분자 유지가 목적) | ~30% | 게이트 A 레퍼럴 축 유지 — 채널 확장(티스토리 정기 등)은 Phase B |
| **P2 — 측정·기술** | 원장·지표·색인 요청(AG) | ~15% | 판정은 주간에 안 함 — 4주/8주 시점에만 |

### 주간 루프 예시 (FLEX — 시간·편수 잠금 아님)

복수 에이전트 초안 + Joseph 루브릭만 하는 주·스프린트 주는 **아래보다 밀도를 올려도 됨.** 숫자는 참고치.

| 요일 | 작업 예시 | 티어 |
|---|---|---|
| 월 | GSC → 대상·타깃 쿼리 확정 (SERP 정찰) | P0 |
| 화·수 | §1–4: title → 도입 200자 → H2 → **루브릭 5문항** (초안은 Claude/GPT/AG 위임 가능) | P0 |
| 목 | 네이버 게시 (그 주 손댄 슬러그 우선) | P1 |
| 금 | 원장 + 지표 기록 | P2 |

### 바쁜 주 최소 생존 버전 — 이 3개 외엔 건너뛰어도 위반 아님

1. **네이버 게시** (게이트 A 분자 — 극단적 부족 주엔 P0보다 우선 가능. 초안이 있으면 부담 작음)
2. **refresh ≥1편** — title(+가능하면 도입) + 색인 요청까지만이라도
3. **원장 1줄**

| 항목 | 처리 |

## Part N — 신규 포스트 파이프라인 (비중 방향 refresh>신규 · 편수 FLEX · KO+EN만)

```
N0 주간 쿼리 배치 → N1 SERP 정찰 → N2 쿼리·골격 확정 → N3 발행 게이트
→ N4 데이터·가설 (기존 Phase 0–2) → N5 KO 원고 → N6 EN 판
→ Cursor 검증 → N7 발행 후 7종 세트
```

### N0. 주간 쿼리 배치 (월요일, 15분 — 신설)

쿼리 후보를 3소스에서 수집해 원장 후보란에 적재:
1. **GSC 실측** — 노출 ≥1 쿼리 중 미커버 의도
2. **니치 교차 조합** — 한일 × 도쿄 × 부동산·세무·실거주 (경쟁 밀도 ≈ 0 공간)
3. **네이버 자동완성·연관검색** (+ 블랙키위 볼륨 — 도입 시)

### N1. SERP 정찰 (쿼리당 5분 — 신설 게이트)

타깃 쿼리를 실제 검색(한국 구글 + 네이버), 상위 10 확인:
- 정부·세무법인·대형 포털이 의도까지 정확히 채움 → **막힘** — 한 단계 긴 꼬리로 이동 후 재정찰
- 포럼·지식인·의도 어긋난 문서·낡은 PDF 혼재 → **열림** — 쿼리 확정

### N2. 쿼리 확정 + title/H2 골격 선행 (신설 — 순서 역전의 핵심)

원고를 쓰기 **전에** 확정한다:
- **title**: 쿼리 프레이즈 1회 **전방 배치** · KO ~30자 · YMYL 가드(추천/보장/무조건/선정 프레이밍 금지 — 제목 층에도 적용)
- **H2 3–5개** = 그 쿼리 검색자의 하위 질문들 (≥1개 질문형 — FAQ JSON-LD 원천)
- 시리즈물은 차별화 요소 전진 배치 ("하치오지·히노·아키시마 실제 집값 — Ep.11" 순서)
- 기록: 원장에 `slug | 타깃 쿼리 | 언어 | 사다리 단수 | 다음 점검일`

### N3. 발행 게이트 (기존 유지 — EDITORIAL_TOPIC_POLICY §4, 6문항)

Hub fit · 검색의도 · 내부링크 ≥2 가능 · 수익화 경로 · **타깃 쿼리 기록됨** · **SERP 열림 확인** — ≥4 Yes(1–4 필수). 미달 시 보류 또는 essay로 강등.

### N4. 데이터·가설 파이프라인 (기존 유지 — AUTHOR_OPS Phase 0–2)

Data Discovery → 티키타카 → Hypothesis Lock → Decision Log. **변경 없음.** 쿼리는 제목·H2 골격에만 관여하고 가설·데이터 층은 침범하지 않는다 — "먼저 결론" spine은 검색의도 완결과 자연 정합(전략화가 voice를 해치지 않는다).

### N5. KO 원고 (vNext spine 유지 + 3항 추가)

- 기존: vNext spine · Evidence L1→L2→L3 · Bear Case · 수치↔출처 1:1 · KO_TERMINOLOGY · 면책 · 정중체(~습니다)
- **추가 ①**: 도입 200자 = 타깃 쿼리에 대한 **완결 답변** (결론·숫자·조건 front-load — 은유적 도입이면 GEO 무효)
- **추가 ②**: 도입이 **한국 거주자/교민의 상황**으로 시작 (한국 세제·송금·비교 맥락)
- **추가 ③**: 본문 확정 후 title 재확인 — 골격(N2)에서 벗어났으면 본문이 아니라 쿼리를 재검토

### N6. EN 판 (직역 금지 — 신설 체크)

- EN은 **그 언어 독자용 문서**: 도입은 global investor 관점, EN 고유 블록 ≥1(해외 구매자 절차 차이 등), title은 EN 검색자 어휘(sentence case)
- **JA 신규 없음** — 동결 유지. hreflang은 방어 코드가 실재 locale만 출력(배포 완료)하므로 KO+EN 발행 안전
- codespell 통과

### N7. 발행 후 7종 세트 (발행 = 이것까지 끝나야 발행)

| # | 작업 | 비고 |
|---|---|---|
| ① | `pnpm validate:post <slug>` + Cursor 검증 통과 | 기존 게이트 |
| ② | pubDatetime/modDatetime 정합 (JST) | MOD_DATETIME_POLICY |
| ③ | **내부링크 ≥2** — tokyoLife 1 + urbanInvestment 1, `/ko/posts/{slug}/` | 링크 0 글 재발 방지 |
| ④ | **FAQ JSON-LD** — H2 질문 3–5개 `extraJsonLd` 연결 | 손댄 슬러그만 원칙과 정합 |

## Part R — 기존 글 refresh 트랙 (편수 = FLEX · 범위 = HARD §1–4)

```
R0 선정 → R1 SERP 정찰 → R2 §1–4 표면 편집 → R3 EN 정합/JA 큐
→ R4 발행 후 세트 → R5 재측정 → (무반응) 선택적 보강 / (악화) 롤백
```

### R0. 대상 선정 (GSC에 통합)

우선순위: **① Sprint 백로그 #1–#10 → ② 백필 큐 #11+ (CONTENT_SEO 부록 C) → ③ Week 5+는 백필이 주 공급원**. 한 주에 몇 편인지는 FLEX. 신호 규칙은 Sprint §3.1 참고.

### R1. SERP 정찰 — N1과 동일 게이트 공유.

### R2. §1–4 표면 편집 (기본 = 한 패스 번들)

**기본 (권장)**: 같은 편집에서 **title(+meta) + 도입 200자 + 질문형 H2**까지 한 번에 (WRITING_GUIDE §1–4). 본문 전체는 건드리지 않는다 (§0.1 HARD).

**옵션 (측정용 FLEX)**: title만 먼저 → 14d/28d 무반응 시 H2·본문 1절(2–4문장)만 추가. 의무 아님.

- 그 글이 FAQ·내부링크 미비면 **같은 세션**에서 처리해도 됨 (별도 리마인더 체계 금지)
- **HARD 금지**: slug/URL · 허브 재배정 · 단정 표현 신설 · 본문 전면 재작성 · 재신청 직전 2주 대량 title
- T4(언어별 uniqueness 전면)는 **코호트 S 소수**만 (§F.2-4) — 전면 확대 금지

### R3. 언어 순서

**KO 먼저 → EN 정합 같은 세션 권고 → JA는 여유 시·KO 선행** (같은 주 다언어 동시 대량 갱신은 피함 — HARD “대량”에 해당하면 금지).

### R4. 발행 후 세트 — N7 ②~⑦ 동일. 특히 **그 주 refresh ≈ 그 주 네이버 게시** (게이트 A 분자).

### R5. 재측정·판정 (Sprint §3.4·§11 · 권고)

- 14d 1차 → 28d 확정. 원장에 개선/무반응/악화 기록
- **악화 시 롤백**: title 갱신 후 28d에 클릭·순위 모두 악화면 이전 title 복원 (이력은 git)
- 같은 URL을 **며칠 만에 반복 갈아엎기**는 피함 (권고). 28일 간격은 측정용 FLEX 가이드라인
