## 1. 최종 확정 — Plan A 우선 전략 (오늘 재확인)

**결론: GSF-Ark(Plan A) 트래픽 확보가 최우선. TokyoKorean(Plan B) AdSense 신청은 보류.**

이것은 새로운 결정이 아니라 **7/8에 이미 내려진 결정을 오늘(7/15) 재확인·고정한 것**이다.

| 트랙 | 상태 | 근거 |
|---|---|---|
| **Plan A — GSF-Ark** | 🟢 **진행 (최우선)** | 근본원인이 "콘텐츠 품질"이 아니라 "외부 신호 부재"로 재진단됨(§3). 트래픽 4트랙 실행이 유일한 실질 해법. |
| **Plan B — TokyoKorean** | 🟡 **보류 (색인 20+ 확보 전까지 신청 안 함)** | 7/5 색인 5~28/91페이지로 매우 낮음. 니치는 유리(非-YMYL)하지만 낮은 색인 상태로 신청하면 같은 실패 패턴 반복 위험. |

**왜 Plan B를 서두르지 않는가 (오늘 재확인한 근거):**
- Plan B가 "더 빠르다"는 직관은 니치 차이(YMYL vs 非-YMYL)에서는 맞지만, **트래픽/색인 부재라는 동일한 약점을 TokyoKorean도 그대로 갖고 있음**(7/5 기준 GSC 색인 5~28건). 니치가 유리해도 "가치 미증명" 상태로 신청하면 승인 확률이 낮아지는 것은 동일한 메커니즘.
- GSF-Ark는 이미 콘텐츠(150편)·기술 인프라·저자 프로필이 갖춰진 **완성된 자산**. 부족한 건 오직 외부 신호(트래픽)뿐 — 이건 "새 사이트를 처음부터 키우는 것"보다 **회수 가능한 투자**에 가깝다.
- 두 사이트를 동시에 신청하면 Google이 같은 게시자 계정을 "저품질 사이트를 양산하는 계정"으로 볼 리스크도 존재(추론, 미검증이지만 배제할 수 없음).

**Plan B 재개 조건 (명시적 게이트)**:
1. TokyoKorean GSC 색인이 20건 이상으로 확인될 것
2. 네이버/커뮤니티 등을 통한 최소한의 오가닉 세션 발생 확인

## 3. "크롤링됨" vs "발견됨" — 시차 문제인가? (Google 공식 문서 기반 검증)

Joseph 질의에 대한 검증 결과 (web search로 Google 공식 설명·Search Central 커뮤니티 확인):

| 상태 | 의미 | 시차(타이밍) 문제 가능성 |
|---|---|---|
| **발견됨-미색인** | Google이 URL 존재만 인지, 아직 콘텐츠를 가져오지 않음 | 🟢 **있음** — 서버 과부하 우려로 재스케줄, 신생/저권위 사이트에 흔함. 단, 이미 색인된 다른 언어 버전이 있으면 크롤 우선순위가 밀릴 수도 있음(John Mueller 코멘트 근거) |
| **크롤링됨-미색인** | Google이 이미 콘텐츠를 가져와 평가까지 마친 뒤 "제외" 결정 | 🔴 **낮음** — Google 공식 도움말: "재제출 불필요"(이미 결론난 상태). 중복/저품질 판정이 원인일 가능성 높음 |

**결론**: 71건(33+38) 전체가 "그냥 기다리면 풀리는 문제"는 아니다. 최소 33건(크롤링됨)은 능동적 배제 판정이며, 다국어 중복 콘텐츠 신호가 유력한 원인.

## 4. hreflang 기술 감사 결과 (코드 레벨 검증 완료)

`src/utils/hreflang.ts`, `src/components/HreflangLinks.astro`, `src/layouts/Layout.astro`, `src/layouts/PostDetails.astro`, `astro.config.ts` 직접 코드 리뷰.

**결론: hreflang 구현 자체는 버그 없음.**

| 점검 항목 | 결과 |
|---|---|
| 자기참조(self-reference) | ✅ en/ko/ja 모두 자기 자신 포함 |
| x-default | ✅ en 매핑 |
| 상호참조(reciprocity) | ✅ 3개 로케일 상호 링크 |
| canonical과 hreflang 충돌 | ✅ 없음 — canonical이 언어별로 각자 자신을 가리킴(EN 하나로 쏠리는 흔한 버그 아님) |
| URL 정규화 | ✅ trailingSlash 설정과 일치 |
| `/ja/posts/6/` 등 이상 URL | ✅ 확인됨 — sitemap 필터(`/\/posts\/\d+$/` 제외)로 이미 제외된 구舊 페이지네이션 잔재. hreflang 버그 아님 |

**구조적 리스크(현재는 미발현)**: `getHreflangAlternateUrls()`가 콘텐츠 컬렉션 존재 여부를 확인하지 않고 URL 패턴만으로 3개 언어 링크를 생성. 지금은 en/ko/ja가 51:51:51로 정확히 일치해 문제없지만, **향후 특정 글을 1~2개 언어만 먼저 발행하면 hreflang이 404를 가리키는 버그가 생길 수 있음.** (낮은 우선순위 — 방어 코드 추가 권장, 지금 당장 급하지 않음)

**핵심 결론**: hreflang은 "이 URL이 어떤 언어용인지"를 알려줄 뿐, "충분히 고유한 콘텐츠인지"는 판단하지 않는다. **hreflang이 완벽해도 3언어 직역 콘텐츠는 여전히 중복으로 판정될 수 있다.**
