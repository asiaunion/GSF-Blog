## 1. 원칙 (Joseph 확정 · 2026-07-17)

**모든 전략은 외부 신뢰 소스를 통한 정보 업데이트 절차를 반드시 거친다.** 최신 정보로 업데이트하고, 해당 분야 전문가들의 조언을 참조해 세우는 것을 기본으로 한다.

**근거 — 낡은 내부 지식은 할루시네이션의 한 형태다.** 외부·최신 자료로 업데이트하지 않고 내부 합의만으로 세운 전략은, 낡았거나 틀린 전제를 현재의 사실처럼 제시한다는 점에서 구조적으로 할루시네이션과 동일한 실패 양식이다. AI 에이전트(Claude·Cursor)는 학습 시점 이후의 변화를 모르고, 인간은 한번 형성된 내부 합의를 재검증 없이 재사용하는 경향이 있다 — 양쪽 모두 이 게이트가 필요하다.

**실증 사례 (2026-07-17, 본 원칙의 촉발점)**: SEO 글쓰기 가이드를 내부 논리+실측만으로 작성 후 외부 대조를 돌린 결과 — 핵심 원칙 6건은 일치했으나, ① Google title 재작성 ~76% 시대의 방어법 ② AI Overviews 발동률 48%(내부 문서는 30~40%로 기록) ③ 네이버 스마트블록 역설계 ④ 네이버 멀티미디어 가점이 누락돼 있었다. 같은 절차로 llms.txt는 도입 전에 **기각**(Google 공식 미지원 확인)할 수 있었고, cool-off 4주는 실무 합의와 일치함을 **확증**할 수 있었다. 외부 검증은 추가 작업을 만드는 게 아니라, 틀린 방향의 작업을 사전에 걸러낸다.

## 2. 하드게이트 규격

### 2.1 발동 조건 (이때는 반드시)

- 전략·정책·프로세스 문서의 **신규 작성**
- 기존 전략 문서의 **대개정** (수치 게이트·우선순위·채널·프로세스 구조 변경)
- **외부 플랫폼 의존 결정** (Google/네이버/AdSense/SNS 알고리즘·정책에 기대는 모든 설계)
- 잠긴 결정이라도 **판정 실패 시 원인 분석** (게이트 미달, refresh 무반응 등)

### 2.2 면제 (게이트가 과설계가 되지 않기 위해 — 이때는 불요)

- **내부 1차 데이터 기반 운영 결정** (GSC/GA4 실측으로 대상 선정, 백로그 순서 조정 등) — 실측 자체가 최신 정보다
- 잠긴 전략 **안에서의** 주간 실행 (P0/P1/P2 루프 수행)
- 코드·빌드·표기 등 기술 실무 (기존 validate/lint 게이트가 담당)
- 이미 검증 유효기간(§2.5) 내인 전제의 재사용

### 2.3 검증 절차 (문서에 "외부 검증" 섹션 필수)

전략 문서는 아래 4항을 담은 **`## 외부 검증` 섹션 없이는 잠금(§F) 불가**:

1. **검증일 + 수행자** (Claude/Cursor)
2. **소스 목록 + 등급** (§2.4) — 각 핵심 전제당 **독립 소스 ≥2** 교차, 가능하면 Tier 1 포함
3. **3분류 결과**: ✅ 확인(내부 전제가 외부와 일치) / ⚠️ 갱신(외부가 더 최신 — 반영 내용) / ❓ 공백(외부 정보 없음 — 가정임을 명시)
4. **재검증 기한** (§2.5)

### 2.4 소스 신뢰 등급

| Tier | 정의 | 예 |
|---|---|---|
| **1 공식** | 플랫폼 1차 문서·공식 발표 | Google Search Central·AdSense Help·네이버 서치어드바이저 공식 블로그·정부 통계 |
| **2 실측** | 대규모 데이터 기반 업계 연구 | Ahrefs/Semrush 스터디, SE Ranking 실측, 공신력 있는 업계 조사 |
| **3 실무 합의** | 복수 독립 실무자의 교차 일치 | 전문 에이전시 블로그·커뮤니티 다수설 (단일 소스 인용 금지) |
| ❌ 불인정 | 단일 블로그 주장·출처 없는 수치·오래된 자료(플랫폼 정책은 12개월+) | — |

Tier 3만으로 결정할 때는 문서에 "실무 합의 수준"임을 명시한다 (공식 근거와 구분).

### 2.5 재검증 트리거 (검증은 1회성이 아니다)

- **시간**: 플랫폼 의존 전제는 **90일** 경과 시 재검증 (알고리즘·정책 영역)
- **사건**: Google 코어 업데이트·네이버 개편·AdSense 정책 변경 공지 시 해당 전제 즉시
- **실패**: KPI 게이트 미달·판정 "무반응/악화" 시 — 원인 후보에 "전제가 낡음"을 반드시 포함

### 2.6 게이트 운영 (누가 막는가)

- **Cursor**: §F 잠금 체크리스트에 **"외부 검증 섹션 존재 + §2.3 4항 충족"** 항목 추가 — 미충족 문서는 잠금 반려
- **Claude**: 전략 문서 작성 시 외부 검증을 산출물에 포함하는 것을 기본 절차로 (웹 리서치 수행 주체)
- **Joseph**: 검증 결과의 ⚠️ 갱신·❓ 공백 항목만 보고받고 판단 — ✅ 확인 항목은 보고 생략 가능 (에너지 절약)
